title: "Current Architecture Choices"
description: "Why the supported Dori Desktop path uses provider-backed files, SQLite, local hybrid search, and a Tauri shell."
---

This page describes the choices visible in the current implementation. It does not claim that every alternative was benchmarked or deployed in production.

---

## 1. Separate Search Cache Instead of a Search Service

Dori keeps search in a rebuildable `vectors.db` rather than running a separate vector-database service. SQLite FTS5 handles keyword retrieval, local Transformers embeddings provide semantic vectors, cosine similarity runs in the Node process, and reciprocal-rank fusion combines the result lists.

This is appropriate for the intended personal-vault scale. Vector comparison currently loads the selected vault's embeddings into the process, so a larger corpus may eventually require a different index strategy.

---

## 2. Local Engine for Desktop-Owned Work

The Desktop engine owns jobs, workflows, watchers, channels, search, and synchronization. Running these concerns locally lets Dori work directly with local files and devices without making a hosted worker the canonical owner of personal state.

Remote vault providers, hosted AI providers, and selected processing capabilities still use network services. The local engine reduces mandatory cloud ownership; it does not make every Dori workflow offline or free of provider charges.

---

## 3. Tauri Desktop Host

Dori uses Tauri v2 for its system tray, process supervision, updater, native commands, and operating-system webview. Unlike Electron, this choice does not bundle a Chromium runtime with the application. Actual memory and startup performance still depend on the operating system, installed capabilities, vault size, and active services.

---

## 4. Node's Built-In SQLite Driver

Dori's SQLite wrapper uses Node 24's `node:sqlite`, avoiding a separately installed `better-sqlite3` database-driver addon. This does not make the entire engine pure JavaScript: local embedding and media-related dependencies can still contain platform-specific binaries.

---

## Summary

| Concern | Current choice | Boundary |
| --- | --- | --- |
| **User content** | Provider-backed Markdown and assets | Remote providers exchange data with their services. |
| **Operational state** | Local SQLite by default | Optional hosted Postgres exists but is not the primary Desktop path. |
| **Search** | Separate SQLite FTS5 and local-vector cache | Derived, rebuildable, and intended for personal-vault scale. |
| **Execution** | Local Node engine | Configured AI, vault, sync, and processing providers may be remote. |
| **Desktop host** | Tauri v2 | Uses the OS webview and ships platform-specific native code. |
