The supported Dori Desktop path keeps the application shell, portal, engine, operational database, and search index on the user's machine. “Local-first” does not mean every configured capability works without a network connection.

## 1. Node 24 SQLite Runtime

Dori's operational and search stores use Node.js 24's built-in `node:sqlite` module instead of `better-sqlite3`. This removes a separately compiled database-driver addon from Dori's own SQLite layer and provides the bundled FTS5 feature used for keyword search.

The complete engine is not free of native dependencies. Local embeddings use `onnxruntime-node`, and other installed packages can include platform-specific binaries such as `sharp`. Desktop releases also contain a platform-specific Tauri executable.

```typescript
// dori-engine/src/sqlite.ts
import { DatabaseSync } from 'node:sqlite';

export default class Database {
  private readonly db: DatabaseSync;

  constructor(filePath: string) {
    this.db = new DatabaseSync(filePath, {
      timeout: 5_000,
      enableForeignKeyConstraints: false,
    });
  }

  transaction<A extends unknown[], R>(fn: (...args: A) => R): (...args: A) => R {
    return (...args: A): R => {
      this.db.exec('BEGIN');
      try {
        const result = fn(...args);
        this.db.exec('COMMIT');
        return result;
      } catch (err) {
        this.db.exec('ROLLBACK');
        throw err;
      }
    };
  }
}
```

## 2. Tauri v2 Desktop IPC & `./dori` CLI

Dori uses Tauri v2 as its native desktop host:
- **Desktop host:** Tauri renders through the operating system webview and supervises the local portal, engine, and optional processing services.
- **Command-line access:** `./dori` exposes supported diagnostics and domain views without requiring the visual interface.
- **Local services:** The portal and engine communicate over local authenticated boundaries owned by the Desktop installation.

## 3. Local Data and Remote Boundaries

User content remains a Markdown and asset tree behind the configured vault provider. A local-filesystem vault can be read without a remote content service. GitHub, Google Drive, and OneDrive vaults exchange content with those providers, and provider capabilities are not identical.

Configured cloud AI providers receive prompts and context required for inference. Local coding-agent CLIs may also use their own network services. OCR, transcription, conversion, and media tools have separate capability and installation requirements.

## 4. Recovery Properties

Engine SQLite stores use WAL mode and explicit transaction boundaries. Derived search indexes can be cleared and rebuilt from vault content. These choices improve recovery from interruption, but they are not a promise of zero corruption under every filesystem, hardware, or process failure.
