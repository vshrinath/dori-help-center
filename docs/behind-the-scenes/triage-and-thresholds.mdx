Dori has two related but separate mechanisms: portal situation summaries use categorical attention labels, while workflows can optionally run a numeric confidence guard. The labels are not a universal machine-learning score assigned to every capture.

## 1. Situation Attention Labels

Dori's portal maps project, thread, and trip state into presentation labels:

- **`needs_you`** indicates a concrete attention signal the portal should surface prominently.
- **`waiting`** indicates work or a dependency that has not completed.
- **`quiet`** indicates a situation without an immediate attention signal.
- **`done`** indicates resolved or completed state where the mapper supports it.

These labels are deterministic projections from the current domain data. They help order and explain UI surfaces; they are not evidence that an AI confidence model evaluated the item.

---

## 2. Optional Workflow Confidence Guard

A workflow can include `ConfidenceGuard` in its `inputGuardrails`. The guard reads `confidence` from the trigger context when it is a number and compares it with the current default threshold of 0.6.

### Pass ($\ge 0.6$): Begin the Workflow
The workflow proceeds to its first step. If the trigger has no numeric `confidence`, the current guard also passes; it does not calculate a score itself.

### Warn ($< 0.6$): Request Review
The execution enters `waiting_review` before running its first step. The engine records an approval-style attention request so the run can be reviewed and resumed.

The guard does not currently learn from manual corrections, assign confidence to every capture, or implement separate high/medium/low routing bands.
