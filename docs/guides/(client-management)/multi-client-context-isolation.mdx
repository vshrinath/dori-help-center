If you manage multiple clients, projects, or separate business entities, context leakage is a real risk. Standard AI chat tools merge all your past conversations into a global memory pool, risking a situation where Client A's financial numbers or strategy end up in a draft for Client B.

Dori avoids this by keeping each client or project in its own folder in your vault, and by scoping what it reads to the project you're working in.

## 1. How It Actually Works

Dori keeps the same project/vault-folder structure it uses everywhere, and applies it deliberately to client separation:

* **Project & Client Vault Folders:** Each client or project lives in its own directory in your Markdown vault (`accounts/{client_name}/`, `projects/{project_name}/`).
* **Scoped by What You're Working In:** When you're drafting or asking questions inside a specific project, Dori's search prioritizes that project's notes over the rest of your vault.
* **You Control the Boundary:** Because everything is plain files in folders, you can see exactly what's filed where, and move or re-tag anything that ends up in the wrong place — no support ticket required to find out why something crossed a boundary.

This is a deliberate design choice, not a missing feature: instead of a hidden access-control layer deciding on your behalf what's safe to surface, the boundary is the folder structure itself — visible, auditable, and yours to correct.

---

## 2. Setting Up Client Organization

1. Go to **Projects → New Project** and create dedicated project spaces for each client.
2. When capturing notes, voice memos, or files, assign them to their respective project tags (or let Dori auto-file them based on client domain rules).
3. When drafting proposals or running meeting prep, select the target project scope so Dori prioritizes that project's notes.
